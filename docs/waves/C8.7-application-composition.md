# C8.7 Application Composition

State: **Complete**

## C8.7.1 Operation Guard Chain
Multiple domain guards execute deterministically after one authorization decision and before the Application boundary. Existing single-guard APIs remain compatible.

## C8.7.2 Typed Multi-Domain Authorized Scope Context
`authz.ScopeKey[T]` provides isolated typed request scope slots so a composite operation may carry Customer, Site, Device, or other domain scopes without a framework-owned universal scope model.

## C8.7.3 Application Capability Ports
`ApplicationDeclaration.requires` declares stable `<domain>/<application>` dependencies. Codegen emits typed capability dependency interfaces and rejects unresolved or cyclic dependencies.

## C8.7.4 Application Dependency Graph
Application and Operation dependencies become explicit `depends_on` edges in Application Graph. Static lint rejects unknown dependencies and cycles.

## C8.7.5 Composite Permission Closure
`OperationDeclaration.requires_operations` declares internal operation dependencies. A composite operation must explicitly contain the transitive permission union of every required operation; lint fails closed when the closure is incomplete.

## C8.7.6 Local UnitOfWork Composition
`requestscope.Compose2/Compose3` build heterogeneous repository sets over exactly one request-owned UnitOfWork, preserving one local transaction around a composite use case.

## C8.7.7 Remote Saga / Outbox Boundary
`framework/workflow/saga` defines validated plans, deterministic idempotency IDs, reverse compensation envelopes, and transactional enqueue through the existing Outbox. `COMPOSITION_REMOTE_SAGA` is an explicit PB boundary; no distributed database transaction is implied.
