# C11.7-A — Multi-Application Runtime Ownership

Status: In progress

Tracking: #97, parent #96

Base: `main@0a9b718e2cac957f11ca551135584b00e1d1f625`

## Real consumer blocker

The qualified C10 `hvritual/biz` runtime has one actual OS process (`cmd/biz`) and one `core.App`, but the canonical contract contains three Applications:

- `deviceops/device_management`;
- `deviceops/site_management`;
- `deviceops/device_transfer`.

The pre-C11.7 DevManifest process model exposes only one `graphNode`. Assigning only one Application would produce incomplete runtime ownership evidence. Assigning the process to a Domain or synthetic node would avoid the Application diagnostics gate and misrepresent the real topology. Starting three copies of Biz would not be the real consumer.

C11.7-A therefore makes explicit runtime ownership plural without changing supervision or execution semantics.

## Contract

Legacy declaration remains valid and unchanged:

```json
{
  "name": "api",
  "command": ["api"],
  "graphNode": "application:device/api"
}
```

Schema-v3 processes may instead declare plural ownership:

```json
{
  "name": "biz",
  "command": ["go", "run", "./cmd/biz"],
  "graphNodes": [
    "application:deviceops/device_management",
    "application:deviceops/device_transfer",
    "application:deviceops/site_management"
  ]
}
```

`graphNode` and `graphNodes` are mutually exclusive. Empty or duplicate plural entries are rejected. Plural ownership requires DevManifest schema version 3.

## Ownership semantics

The declaration remains fully explicit:

- no node is discovered from process name, argv, port, package path, or diagnostics output;
- ownership is normalized deterministically;
- every owned node must already exist in the canonical Application Graph;
- a graph node can have only one process owner in the current closure plan;
- closure mode requires every process to own at least one explicit graph node.

If at least one owned node is an Application, the existing process-level diagnostics readiness contract applies:

- explicit readiness;
- `diagnosticsReady=true`;
- `captureDiagnostics=true`;
- captured canonical `core.App` diagnostics must be live and ready.

One process hosting multiple Applications therefore supplies one canonical `core.App` diagnostics snapshot for that process. C11.7-A does not fabricate per-Application health states.

## Runtime evidence

`ProcessRuntimeReport` keeps legacy `graphNode` and adds optional `graphNodes`.

- legacy singular manifests continue to emit only `graphNode`;
- plural manifests emit deterministic `graphNodes` and leave `graphNode` empty;
- runtime status text uses `graph=` for legacy singular evidence and `graphs=` for plural evidence;
- runtime graph generation emits one explicit `runs` edge from the process node to each owned graph node.

The runtime report schema version remains unchanged because the field is additive and legacy serialized evidence is preserved.

## Preserved boundaries

C11.7-A does not change:

- process creation, signals, shutdown ordering, or the DevRuntime supervisor;
- readiness HTTP probing or canonical diagnostics parsing;
- protobuf/OperationPlan/AssemblyPlan compilation;
- generated Runtime Assembly;
- `framework/operation.Executor`;
- root `ExecutionScope` transaction/UoW/idempotency ownership;
- `core.App` lifecycle ownership;
- Project Profile ownership;
- business authorization or business semantics.

## Permanent qualification tests

`pkg/devruntime/c11_7_multi_application_ownership_test.go` proves:

1. one real process can explicitly own three Application nodes;
2. plural nodes normalize deterministically;
3. one diagnostics readiness barrier satisfies that process-level Application ownership contract;
4. the runtime report preserves all three owned nodes;
5. runtime graph generation emits three `runs` edges;
6. `ValidateRuntimeClosure` accepts complete multi-Application evidence;
7. singular + plural declarations fail closed;
8. empty/duplicate plural nodes fail closed;
9. plural ownership on pre-v3 manifests fails closed;
10. duplicate ownership across processes fails closed;
11. ownership drift in a runtime report fails closed;
12. legacy singular report JSON does not gain a `graphNodes` field.
