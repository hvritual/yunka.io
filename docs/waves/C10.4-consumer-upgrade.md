# C10.4 — Consumer Upgrade

## Status

- State: **In progress**
- Tracking: issue #50
- Framework base: qualified C10.3 exact head `561d9c779334371735acf8d394969cb752e3999d`
- Real consumer baseline: `hvritual/biz` `agent/c9-9-conformance-closure@1c66672ba981c083a84997e0dbbd23331905f9cb`

## Goal

Use the real `hvritual/biz` Device Transfer slice to prove C10 removes structural framework plumbing without weakening the C9.8/C9.9 execution truth.

The preserved business/execution path is:

```text
device.transfer
  -> site.validate_transfer_target
  -> handwritten business decision
  -> device.update
```

C10.4 is a consumer-pressure wave. A Yunka change is allowed only after the migration demonstrates either a P0 compiler defect or a P1 missing generic assembly seam.

## Consumer baseline truth

The C9.9 consumer already proves:

- `site.validate_transfer_target` is a canonical internal Operation with no fake REST/gRPC exposure;
- `device.transfer` declares both `site.validate_transfer_target` and `device.update` child Operations;
- transitive permission closure is explicit;
- one root authorization occurs before the Application boundary;
- one root local ExecutionScope/UoW owns the transaction;
- generated child capabilities enter `ExecuteChildTyped` and join that root scope;
- Applications do not own permission evaluation or root transaction lifecycle;
- internal-only DTOs do not leak into external projections;
- durable idempotency and Saga/Outbox behavior remain canonical C9 semantics.

These are migration invariants, not implementation details to rewrite.

## Before — handwritten framework plumbing inventory

The qualified C9.9 Biz tree still contains structural assembly that C10 is intended to replace.

### `cmd/biz/main.go`

Structural framework plumbing:

- imports module autoload for activation;
- builds `platform.Provider` manually;
- calls `kernel.New` with `modulecatalog.Default()`;
- starts and shuts down `core.App` explicitly.

Consumer-owned and expected to remain handwritten:

- process environment parsing;
- MySQL DSN/pool configuration;
- module product configuration;
- bootstrap values/secrets;
- signal/shutdown budget selection.

### `modules/deviceops/module.go`

Structural framework plumbing targeted for elimination where C10 already owns it:

- construction of canonical `operation.Executor` dependencies;
- handwritten Application instance wiring;
- handwritten generated child-capability constructor wiring;
- manual canonical REST registration;
- manual canonical gRPC registration;
- listener/server lifecycle bookkeeping;
- duplicated server health/shutdown participation.

Consumer-specific logic that remains legitimate:

- access-store/bootstrap/migration behavior;
- authentication middleware/interceptor adapters;
- Device OperationGuard construction and policy interpretation;
- repository factory creation;
- handwritten Application/service constructors;
- concrete listener addresses/TLS/process configuration.

## Hard migration target

For migrated canonical Operations, remove structural categories rather than optimize for a percentage:

- manual REST registration: **0**;
- manual gRPC registration: **0**;
- manual Application dependency/child-capability wiring that generated assembly can express: **0**;
- manual root authorization sequencing: **0**;
- manual root transaction/requestscope orchestration: **0**;
- duplicate lifecycle/health/diagnostic registration for C10-owned runtime components: **0**.

Business construction and product configuration are not counted as framework plumbing.

## Framework Pressure classification

Every migration workaround is classified before Yunka changes:

### P0 — Compiler defect

A fact already declared in the supported Contract/Assembly model cannot be generated or joined correctly.

A P0 may be fixed in C10.4 with the smallest correctness patch and permanent regression evidence.

### P1 — Missing generic assembly seam

Structural wiring is demonstrably repeated/required but cannot be expressed through current typed C10 bindings without consumer-owned framework plumbing.

A P1 requires a generic seam, no Biz business semantics, and executable consumer proof.

### Consumer-specific

Configuration, authentication implementation, migration/bootstrap, business constructor, domain guard, policy interpretation, or other product fact belonging to Biz.

It must remain in Biz and must not become Yunka DSL/runtime behavior.

### Deferred framework pressure

Potentially reusable behavior with only one consumer proof or requiring new semantics outside current C10 contracts.

Record it; do not implement it in C10.4.

## Migration sequence

1. Create a Biz migration branch from the qualified C9.9 consumer head.
2. Run the unmodified consumer against qualified C10.3 to establish compatibility and capture the exact before inventory.
3. Add C10 `assembly generate/check` to the Biz generation path and inspect deterministic output.
4. Bind handwritten Biz Applications/config/security/platform/transport resources through generated typed assembly.
5. Remove only structural manual wiring replaced by generated C10 assembly.
6. Classify every blocker before changing Yunka.
7. Regenerate twice and require byte-for-byte zero drift.
8. Run Biz `make verify` and MySQL 8.4 `make pressure`.
9. Re-run internal-Operation/no-exposure, permission-closure, one-authz, one-UoW/shared-scope assertions.
10. Record before/after plumbing inventory and all remaining pressure.

## Validation gate

C10.4 is complete only when the exact real consumer tree:

- regenerates through the C10 contract + assembly compiler;
- has second-generation zero drift;
- passes standard consumer verification;
- passes MySQL 8.4 pressure/integration;
- preserves shared-UoW and child Operation semantics;
- preserves internal-only no-external-exposure;
- preserves authorization and permission closure;
- contains no manual canonical REST/gRPC registration for migrated Operations;
- contains no Application-level framework authorization/transaction bypass;
- records all remaining pressure explicitly.

## Rollback

The Biz migration remains based on the qualified C9.9 consumer truth and may revert to that generated/manual typed assembly path until C10.5. C10.4 must not make an irreversible consumer cutover before zero-drift and MySQL pressure pass.
