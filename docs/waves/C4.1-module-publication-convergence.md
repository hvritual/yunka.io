# C4.1 Module Publication Convergence

## Goal

Make Yunka's publishable Go modules independently consumable outside the repository workspace.

## Canonical module identities

- `github.com/hvritual/yunka.io/pkg`
- `github.com/hvritual/yunka.io/framework`
- `github.com/hvritual/yunka.io/gateway`

`app` remains the repository-owned developer/tooling module and is not part of the public module release set.

## Dependency order

`pkg -> framework -> gateway`.

Publishable module `go.mod` files must not contain local `replace` directives. The repository `go.work` is only a development composition surface and is not a release contract. `go work sync` is deliberately excluded from release qualification because it can project workspace-wide MVS selections back into otherwise independent modules.

## Compatibility decision

The repository-owned module that impersonated `github.com/go-kit/kit` is removed from the release graph. The Aliyun SLS SDK's historical `github.com/go-kit/kit/log` imports resolve through the actual upstream Go kit module instead of a consumer-invisible local replacement.

## Qualification

C4.1 is qualified only when the exact tagged candidate passes:

1. source-workspace `test/vet/build` with all four repository modules;
2. each publishable module's `GOWORK=off test/vet/build`;
3. no publishable `go.mod` contains `replace`;
4. a clean external consumer fetches the same release version of pkg/framework/gateway.

The first qualification release is `v0.1.0-c41rc2`; failed qualification deletes the RC tags. Stable tags are created only after canonical integration.

## RC2 dependency convergence

RC1 validated the GitHub multi-module identity and tag layout, but removing the
repository-local go-kit compatibility module exposed the historical
`github.com/go-kit/kit v0.10.0` dependency graph. That graph reaches the removed
`github.com/lyft/protoc-gen-validate v0.0.13` repository through old Zipkin/gRPC
dependencies. RC2 raises `github.com/go-kit/kit` to `v0.13.0`, which preserves
the legacy `kit/log` and `kit/log/level` compatibility packages used by the
Aliyun SLS SDK while using the maintained dependency graph. No local `replace`
is added to any publishable module.
