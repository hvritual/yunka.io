# C9.7 — Execution Semantics Closure

## Goal

Close the execution-mechanism gaps exposed by real `hvritual/biz` pressure after C9.1–C9.6 unified OperationPlan + Executor.

C9.7 makes the root Operation execution scope the owner of transaction/UoW and durable idempotency semantics while keeping Application code focused on business decisions.

## Scope completed

1. PB ExecutionPolicy for explicit transaction and idempotency declarations.
2. OperationPlan schema v2 execution IR.
3. Root ExecutionScope and transaction lifecycle ownership.
4. Join-only RequestScope repository views.
5. Local Child Operation runtime with undeclared-child and transaction-escalation fail-closed behavior.
6. Generated typed child capability invocation through `ExecuteChildTyped`.
7. Saga/Outbox staging through current ExecutionScope transaction.
8. Durable Operation-level idempotency with MySQL-backed lease/fencing and atomic success staging.
9. Fixed Executor phase closure for security/idempotency/scope/application/transaction/outcome.
10. Execution policy evidence in graph/diagnostics.
11. Real Biz regeneration + verification + MySQL 8.4 pressure conformance.
12. Permanent architecture policy preventing execution-mechanism leakage back into core/Application boundaries.

## Runtime invariant

```text
PB Operation
  -> Contract Compiler
  -> immutable OperationPlan
  -> Unified Executor
       -> metadata
       -> security once
       -> idempotency claim
       -> root ExecutionScope / UoW
       -> Application / typed child composition
       -> Saga/Outbox joins current transaction
       -> atomic idempotency success staging
       -> one commit / rollback
       -> outcome
```
