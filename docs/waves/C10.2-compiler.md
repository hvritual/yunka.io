## Delivered compiler

C10.2 compiles the qualified AssemblyPlan and existing canonical type-resolution facts into deterministic typed Go structural assembly. Generated code owns framework wiring only; handwritten code owns business behavior.

The generated surface includes:

- typed `ApplicationFactories` and deterministic `BuildApplications`;
- typed Application dependency values from explicit `ApplicationDeclaration.requires` facts;
- existing C9 generated child capabilities using canonical `ExecuteChildTyped` semantics;
- deterministic `TransportBindings` / `RegisterTransports` only for explicit AssemblyPlan bindings;
- explicit `KernelDependencies` / `KernelOptions` seams without starting a second runtime;
- `ExpectedModuleRequirements`;
- an explicit generated static module `NewCatalog()` from qualified generated module binding evidence;
- AssemblyPlan digest binding between deterministic plan bytes and generated Go.

The canonical consumer artifacts are:

- `contracts/generated/assembly-plan.json`;
- `internal/assembly/zz_yunka_assembly_gen.go`;
- `internal/assembly/zz_yunka_modules_gen.go`.

## Module binding boundary

Module Go binding is derived only from existing explicit generated module files under the caller-supplied module root. The compiler does not infer import paths from directory/module names and does not execute module packages while compiling.

Forbidden mechanisms remain absent:

- reflection DI;
- `go/packages` or plugin discovery;
- runtime package/filesystem scanning;
- service locator or string-keyed Application registry;
- hidden package-global runtime registration;
- inferred REST/gRPC exposure;
- generated business implementation.
