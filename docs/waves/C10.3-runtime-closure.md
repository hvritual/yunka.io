## Goal and closure

C10.3 closes C10 generated assembly through the existing Yunka runtime spine without introducing a second runtime owner:

```text
AssemblyPlan
   ↓
generated typed Bootstrap
   ↓
framework/kernel
   ↓
core.App                      ← only lifecycle owner
   ↓
Platform Provider
   ↓
typed Modules
   ↓
Applications + C9 Executor
   ↓
explicit REST / gRPC / internal Operations
   ↓
Health + Diagnostics + Application Graph
   ↓
yunka dev readiness / closure
```

C10.3 does not own new authorization, transaction, idempotency, identity, request scope, business dispatch, listener discovery, shell-command discovery, deployment topology, or restart policy.

## A — App-owned runtime components

`core.RuntimeComponent` is a lifecycle-only leaf with an explicit name and Start/Health/Shutdown callbacks. It deliberately carries no service payload, lookup API, registry, or runtime field injection.

`core.App` remains the sole lifecycle owner:

1. Platform/ContextFactory starts;
2. typed modules start in deterministic catalog order;
3. runtime components start in deterministic name order;
4. health covers Platform/modules/runtime components;
5. shutdown reverses runtime components first, then modules, then Platform capabilities.

`core.RuntimeInventory` is secret-free read-only evidence for explicit route/RPC presence, not an execution registry.

## B — Kernel bootstrap

`kernel.Bootstrap[T]` is sequencing, not a runtime object:

```text
kernel.New
  -> typed Build
  -> typed Register
  -> existing App.Start
```

Its result contains the existing `*core.App` plus typed Applications and has no Start/Shutdown methods. Build/Register failure cleans the constructed App; `core.App.Start` remains responsible for lifecycle-start rollback.

## C — Generated runtime bootstrap

Only `CompileBoundAssembly` receives runtime bootstrap augmentation because that path has already proved explicit generated module Go bindings and `NewCatalog()`.

Generated `Bootstrap` reuses:

- generated explicit `NewCatalog()`;
- existing Platform Provider;
- generated `BuildApplications`;
- existing C9 `operation.Executor`;
- generated `RegisterTransports`;
- `kernel.Bootstrap`.

Static runtime inventory is derived only from canonical AssemblyPlan binding references joined to canonical Manifest paths. Internal-only Operations remain transport-free.

## D — Explicit HTTP/gRPC lifecycle adapters

`framework/runtimecomponent` adapts caller-owned standard servers into App-owned lifecycle leaves.

HTTP requires explicit `*http.Server + net.Listener` and uses bounded `http.Server.Shutdown(ctx)`.

gRPC requires explicit `*grpc.Server + net.Listener` and uses `GracefulStop`, falling back to `Stop` when the supplied shutdown context expires.

Neither adapter infers listener addresses, TLS, secrets, environment, deployment topology, shell commands, or restart policy.

## E — Diagnostics and Application Graph closure

Existing `core.App.Diagnostics` remains the runtime inventory source. Application Graph projects:

- runtime components as observed nodes;
- explicitly bound routes as observed runtime-route nodes;
- modules as observed runtime modules;
- process ownership from dev manifest as declared evidence;
- live process/diagnostic snapshots as observed evidence.

No graph edge is inferred from package names, process names, URL shape, or method naming.

## F — `yunka dev` closure hardening

Historical W10 non-Application dependency processes retain explicit graph ownership without being forced to expose Yunka diagnostics.

When a closure process explicitly owns an Application Graph node (`kind=application`), `yunka dev plan|run --closure` fails closed unless it declares:

```text
Readiness != nil
DiagnosticsReady = true
CaptureDiagnostics = true
```

`yunka dev status --closure` rebuilds the current explicit plan from developer-authored config, Application Graph/contract graph, targets and closure mode, then validates the runtime report against that plan. It does not trust a state JSON in isolation.

Closure status requires matching application identity, deterministic process plan, complete/duplicate-free inventory, exact graph ownership, correct running/ready states, and live/ready captured diagnostics for Application owners. Stopped, failed, stale, ownership-drifted, partially ready, or diagnostics-free state fails closed.

F adds no command generation, listener/port discovery, process-name-to-Application inference, package scanning, secret discovery, or restart inference.

## Permanent architecture boundary

`pkg/architecturepolicy/c10_3_test.go` protects these invariants:

- `core.App` remains the only lifecycle owner;
- generated bootstrap does not duplicate authz/UoW/runtime semantics;
- RuntimeComponent cannot grow into a service registry;
- transport adapters cannot create/infer listeners;
- generated assembly cannot directly own Start/Shutdown;
- dev closure cannot infer commands or runtime topology;
- Application-owner diagnostics barriers remain explicit;
- `status --closure` must use plan-based `ValidateRuntimeClosure`.
