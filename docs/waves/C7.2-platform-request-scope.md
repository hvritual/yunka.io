# C7.2 — App-owned Platform Provider and Request Scope

## Status

Foundation subwave over `main@5b605ad1eb1a632071a7e00c155399519afed891` (C7.1). This change establishes the resource and request-lifetime contracts required before the first production module is moved off the legacy reflection container.

## Goal

Preserve the original framework ergonomics:

```go
import _ "example.com/service/modules/orders/autoload"
```

A module continues to contain no configuration lookup, DSN parsing, database/RPC connection construction, global App access, or pool-return code. It declares named requirements and receives a restricted typed build context. C7.2 adds the missing runtime owners behind that contract.

```text
blank import descriptor
        ↓
Catalog.Seal + aggregate requirements
        ↓
App-owned Platform Provider
        ↓
generated typed module wiring
        ↓
stateless service
        ↓
RequestScopeFactory.New(ctx)
        ↓
request-owned Unit of Work + repositories
```

## Platform Provider

`framework/platform.Provider` is a `modulecatalog.ContextFactory` owned by one App instance. It:

- accepts typed config/logger/event-bus capability sources;
- owns named database and typed gRPC factories;
- opens only capabilities required by the sealed plan;
- opens each required name exactly once;
- fails before any module Build when a requirement is missing;
- exposes only the current module's declared capability view;
- prefixes the supplied logger with the stable module name;
- starts and health-checks resources in deterministic key order;
- shuts resources down in reverse order;
- cleans already-opened resources when prepare/start fails;
- is idempotent under repeated prepare/start/shutdown calls;
- never stores resources in the process-default descriptor catalog.

`kernel.Options.Platform` is the preferred composition entry. It cannot be combined with direct capabilities or a second `ContextFactory`, preventing two competing ownership paths.

The App remains the owner of the shared EventBus because the existing lifecycle already closes it. The Platform Provider owns named DB/RPC resources. A composition build failure now closes the App-owned EventBus as well as the capability provider and already-built modules.

### Production factories

The platform package includes:

- `MySQLFactory` with typed pool configuration and App-owned `sql.DB` close semantics;
- `GRPCFactory` requiring explicit transport credentials;
- TLS credential construction with optional CA and client certificate inputs;
- managed and borrowed resource constructors for embedding and tests.

Modules never receive DSNs, TLS file paths, or connection factories.

## Request Scope

`framework/requestscope` establishes a request-owned boundary independent of legacy `request.Runtime`:

```text
context.Context
 ├─ trusted Principal snapshot
 ├─ runtime Metadata snapshot
 ├─ trace ID
 ├─ request logger
 ├─ UnitOfWork
 └─ typed repository set
```

A `Factory[R]` begins one fresh Unit of Work and builds one typed repository set for every request. No Scope, repository, transaction, Principal, or Context enters `sync.Pool` or a singleton Service field.

### Finalization contract

- callback success: `Commit → Close`;
- callback error: `Rollback → Close`;
- callback panic: `Rollback → Close → re-panic original value`;
- direct `Close` on an open Scope: implicit rollback, then close;
- `Commit`, `Rollback`, and `Close` are concurrency-safe and idempotent;
- commit and rollback are mutually exclusive;
- repository or logger construction failure/panic rolls back and closes the acquired Unit of Work;
- rollback cleanup detaches request cancellation while preserving trusted context values;
- a failed commit remains rollback-eligible and preserves both commit and cleanup errors.

`GORMFactory` starts exactly one transaction from an App-owned GORM pool, including when explicit `sql.TxOptions` are supplied. `GORMRepositories` binds module-specific repositories to that transaction. Closing a request Unit of Work never closes the App-owned database pool.

## Architecture policy

The C7 architecture gate now includes:

```text
framework/core/modulecatalog
framework/kernel
framework/platform
framework/requestscope
```

These paths may not import `reflect`, the legacy reflection module container, `pkg/di`, or legacy `request.Runtime`; may not use `sync.Pool`; and may not call global service-locator APIs.

## Deferred real-module migration

This foundation intentionally does not delete or silently adapt the legacy container. C7.2.3 will migrate the Gateway Role typed RPC vertical slice onto these contracts, reduce the `ModuleGatewayProvider → GetService/SetRuntime/PutService` compatibility path, and keep the one-line autoload experience. C7.3 deletes the old container only after real consumers have moved.

## Rollback

Revert the single C7.2 foundation commit. Existing legacy modules remain operational because this subwave adds an isolated typed ownership path and does not change protobuf contracts or persisted schemas.
