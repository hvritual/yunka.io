## Goal

Adapt the existing read-only Doctor evidence to the C11.3 diagnostic contract without changing probes or Doctor truth.

## Architecture

```text
pkg/devruntime.Doctor
  Check{name,status,detail,action}
            ↓ unchanged
exact check-name mapping table
            ↓
  pkg/diagnostic.Diagnostic
            ↓
       text / json
```

The adapter maps exact existing probe names. It does not infer a stage from arbitrary strings. An unmapped future probe fails the adapter so a stable diagnostic code must be assigned deliberately.

## Severity and strict semantics

| Doctor status | Diagnostic severity |
|---|---|
| `pass` | `info` |
| `warn` | `warning` |
| `fail` | `error` |

`--strict` does not rewrite warnings as errors. It only changes command success truth:

```text
warning + strict=false -> diagnostic severity=warning, ok=true, exit=0
warning + strict=true  -> diagnostic severity=warning, ok=false, exit=1
```

## Stable namespaces

- workspace/project root -> `YUNKA-DX-PROJECT-101`
- Go workspace/toolchain lock/tools -> `YUNKA-DX-TOOLCHAIN-1xx`
- contract manifest/Application Graph -> `YUNKA-DX-CONTRACT-1xx`
- git/dev manifest -> `YUNKA-DX-DEV-1xx`

## Output constraints

- text and JSON are generated from the same normalized diagnostics;
- Doctor JSON does not serialize `DoctorReport.Root`;
- absolute project-root occurrences in check detail/actions are normalized to `.`;
- remediation remains descriptive and is never executed;
- unsupported `--format` uses the existing `YUNKA-DX-DEV-001` CLI diagnostic;
- blocking Doctor results return an empty structured exit so no timestamp trailer is appended.

## Non-goals

- no `doctor --fix`;
- no tool installation;
- no project mutation;
- no changes to tool/version probes;
- no changes to contract graph validation;
- no changes to git-status or dev-manifest checks;
- no changes to runtime readiness/closure.

## Qualification

C11.3-C is qualified only when:

1. all current Doctor check names have explicit stable mappings;
2. pass/warn/fail severity translation is exact;
3. strict mode changes only final success/exit truth;
4. project absolute root is absent from JSON output;
5. remediation actions survive as non-executing structured actions;
6. Doctor remains read-only;
7. existing expert/runtime behavior is unchanged;
8. full CI, Determinism recheck, production/MySQL 8.4, and clean-worktree gates pass on the exact head.
