## Goal

Establish deterministic, machine-local evidence that can later prove whether a fast feedback path is safe to consider. C11.4-A does **not** skip contract compilation, module validation, assembly compilation, or drift checks.

The evidence contract records:

```text
engine identity
+ protoc/tool identity
+ canonical developer-workflow inputs
+ current generated outputs
        ↓
.yunka/cache/fast-feedback.json
```

The cache is disposable optimization evidence only. Deleting it must never change correctness.

## Canonical input coverage

For the C11.1/C11.2 developer workflow, input evidence covers the facts that can change generated contract/application/assembly output:

- `.yunka/project.json` when present, with a deterministic missing marker when absent;
- `go.mod` when present;
- canonical contract source inventory plus every source root/proto path referenced by that inventory, or the conventional/configured proto root;
- every explicit additional `--proto-path` in precedence order;
- the configured/conventional module root;
- engine identity and protoc executable identity outside the tree digest.

Absolute host paths are never serialized into cache metadata. External proto roots are represented by stable logical labels plus content digests.

## Output coverage

Output evidence covers:

- the configured/conventional contract generated directory;
- the configured/conventional generated Go root.

C11.4-A intentionally fingerprints the generated Go root conservatively. If handwritten files coexist under that root, their change may cause a false cache miss, but never a false cache hit. Precision can be narrowed only after a later wave proves a canonical generated-file inventory.

## Fingerprint algorithm

`sha256-tree-v1` hashes stable logical root labels, relative file names, entry type markers, and file bytes in deterministic order. It does not hash absolute host paths or mtimes.

Rules:

- root order is canonicalized by logical label;
- caller labels encode precedence where order is semantically significant (for example `contract.protoPath.000`);
- missing optional roots contribute an explicit `missing` marker;
- file renames change the digest even when bytes are identical;
- mtimes and filesystem inode metadata are ignored;
- directory symlinks are not accepted as reusable evidence;
- file symlinks are fingerprinted by the bytes the compiler would read;
- cache corruption/unsupported schema is an ordinary cache miss in later waves, never a correctness error.

## Engine identity

A cache hit is safe only when the running Yunka engine has a verified identity.

Preferred identity order:

1. clean VCS revision embedded by Go build information;
2. released module version;
3. unverified schema fallback.

The fallback may be recorded for diagnostics but is **not reusable**. Dirty VCS builds are also non-reusable because their source content cannot be proven by the commit SHA alone.

## Persistence

Canonical local cache path:

```text
.yunka/cache/fast-feedback.json
```

The file contains no timestamps, secrets, DSNs, tokens, request IDs, or absolute project paths. Serialization is deterministic and atomic.

`yunka generate` may record evidence only after canonical generation succeeds. Evidence-recording failure is non-blocking because the cache is optional. `yunka check` remains read-only and does not create, update, repair, or delete the cache.

## Definition of done

- deterministic tree fingerprint package exists with no dependency on compiler/runtime packages;
- metadata schema validates strictly and serializes deterministically;
- file content/path/missing-root changes invalidate fingerprints;
- engine/toolchain/input/output mismatch prevents reuse;
- unverified/dirty engine identity prevents reuse;
- projectflow can derive safe logical input/output root sets from C11.2 resolved project facts;
- successful full `yunka generate` records disposable evidence without changing generated artifacts;
- `yunka check` never writes cache state;
- no validation/compiler stage is skipped in C11.4-A;
- full CI + determinism + production/MySQL 8.4 + clean worktree pass on exact head.

## Non-goals

- no daemon/watch mode;
- no cached semantic compiler result;
- no change to authorization, transaction/UoW/idempotency, Runtime Assembly, or runtime closure semantics.
