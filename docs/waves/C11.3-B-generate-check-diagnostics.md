## Goal

Adopt the qualified C11.3-A diagnostic contract in `yunka generate` and `yunka check` while preserving C11.1/C11.2 compiler, validation, drift, and read-only semantics.

## Design

```text
canonical project/contract/module/assembly logic
                  ↓
         typed Failure metadata
       kind / root / location / cause
                  ↓
           projectflow.Diagnose
                  ↓
             pkg/diagnostic
                  ↓
          text             json
```

The typed failure wrapper does not decide whether a contract/module/assembly is valid. It only records which canonical stage returned the failure.

## Stable failure classes

| Class | Code | Remediation |
|---|---|---|
| project/profile resolution | `YUNKA-DX-PROJECT-001` | review `.yunka/project.json` |
| contract compile/lint/generation | `YUNKA-DX-CONTRACT-001` | fix canonical contract error |
| contract/application generated drift | `YUNKA-DX-CONTRACT-002` | `yunka generate` |
| module validation/discovery | `YUNKA-DX-MODULE-001` | `yunka module check` |
| assembly compile/generation | `YUNKA-DX-ASSEMBLY-001` | fix canonical topology/input error |
| assembly generated drift | `YUNKA-DX-ASSEMBLY-002` | `yunka generate` |
| unsupported CLI output format | `YUNKA-DX-DEV-001` | use `text` or `json` |

## Output contract

### Text

Default behavior remains human-oriented. Failures include code, stage, summary, optional project-relative location/detail, and descriptive remediation actions.

### JSON

`--format json` emits deterministic JSON without host-specific root fields or timestamps. Success includes ordered stage results. Failure uses the C11.3-A diagnostic envelope and exits non-zero.

## Exit behavior

Machine-readable failures are printed before returning an empty `cli.ExitCoder`. The top-level runner preserves its exit code without adding a second timestamped `log.Fatal` line. Non-C11.3 expert-command errors keep their existing error path.

## Invariants

- `yunka check` remains read-only.
- no validation rule moves into `pkg/diagnostic`, `dxoutput`, or CLI rendering.
- no string matching is used to infer canonical failure stages.
- protobuf, OperationPlan, module descriptors, AssemblyPlan, Executor, ExecutionScope, and runtime closure semantics are unchanged.
- JSON output does not expose the absolute project root.

## Qualification

C11.3-B is qualified only when:

1. text and JSON success paths are deterministic;
2. each canonical failure class has a stable code;
3. project absolute paths are sanitized from diagnostic detail/location;
4. generated drift produces a `yunka generate` remediation action;
5. `yunka check` remains read-only under drift;
6. JSON failure exits non-zero without a timestamped trailer;
7. expert commands remain compatible;
8. full CI, Determinism recheck, production/MySQL 8.4, and clean-worktree gates pass on the exact head.
