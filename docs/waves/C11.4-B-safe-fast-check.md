## Goal

Use the qualified C11.4-A evidence to bypass expensive developer-loop recomputation only when a cache hit is fully proven. The canonical `projectflow.Check` implementation remains unchanged and authoritative.

## Decision model

```text
yunka check
   ↓
resolve project
   ↓
load local evidence
   ├─ missing / corrupt / unsupported ───────────────→ canonical full Check
   ↓
recompute current engine/tool/input/output evidence
   ├─ capture error ─────────────────────────────────→ canonical full Check
   ├─ engine unverified/dirty ───────────────────────→ canonical full Check
   ├─ any engine/tool/input/output mismatch ─────────→ canonical full Check
   ↓
exact verified evidence hit
   ↓
return explicit fast-check success evidence
```

A fast hit reports only that the fingerprint evidence was verified. It does not pretend that contract/module/assembly stages ran during this invocation.

## Read-only rule

`yunka check` must not write, repair, refresh, delete, or migrate `.yunka/cache/fast-feedback.json` on either hit or fallback. A successful full fallback is still read-only. Cache refresh remains owned by generation in later slices.

## Forced full path

`yunka check --full` bypasses all fast-feedback evidence and invokes canonical `projectflow.Check` directly. This is the developer escape hatch and a permanent comparison path for qualification.

## Safety properties

- cache is optional optimization evidence only;
- missing/corrupt cache can never block a valid project;
- source/profile/module/tool/engine changes invalidate a hit;
- generated-output edits invalidate a hit and force canonical drift detection;
- dirty/unverified Yunka builds cannot use the fast path;
- evidence mismatch never returns an error by itself; it falls back to canonical truth;
- no cache state is used by CI/`make verify` as correctness truth.

## Definition of done

- top-level `yunka check` uses a fast-feedback wrapper while `projectflow.Check` remains full/canonical;
- exact verified evidence hit bypasses the injected canonical checker in regression tests;
- missing/corrupt/unverified/mismatched evidence always calls canonical full check;
- output fingerprint drift falls back and canonical drift failure is preserved;
- `--full` always calls canonical full check;
- fast hit text/JSON is deterministic and explicitly named `fast-check`;
- cache bytes are unchanged on hit, miss, full fallback, and failure;
- full CI + determinism + production/MySQL 8.4 + clean worktree pass on exact head.

## Non-goals

- no incremental generation;
- no cache update from `check`;
- no semantic compiler result cache;
- no watch daemon;
- no authorization/UoW/transaction/idempotency/runtime changes.
