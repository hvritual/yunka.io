## Scope

This slice introduces the leaf developer diagnostic schema and deterministic renderers only. It deliberately does not adapt `generate/check/doctor` yet; those are later C11.3 slices after the schema qualifies.

Permanent boundary:

```text
canonical validator / compiler / Doctor probe
              ↓
        adapter boundary
              ↓
       pkg/diagnostic
              ↓
        text / JSON UX
```

`pkg/diagnostic` cannot become a validator, auto-fixer, command executor, runtime diagnostic service, or secret-bearing error sink.

## First implementation

The initial contract includes:

- `Severity`: error / warning / info;
- stable `YUNKA-DX-<DOMAIN>-NNN` code validation;
- stage and concise summary;
- optional detail;
- optional project-relative location/ref;
- structured action kinds: command / edit / docs;
- deterministic normalization and ordering;
- deterministic JSON envelope with schema version / command / ok / diagnostics;
- text rendering from the same normalized diagnostic objects;
- rejection of absolute host paths in structured locations;
- rejection of unsupported action kinds so remediation remains descriptive and non-executing.

## Qualification

C11.3-A is complete only when:

- focused package tests pass;
- JSON output is byte-stable for input permutations;
- error-before-warning ordering is deterministic;
- absolute-path leakage is rejected;
- invalid code/action identities are rejected;
- package remains dependency-neutral;
- repository architecture/dependency/full CI gates remain green.
