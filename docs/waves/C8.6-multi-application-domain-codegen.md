# C8.6 Multi-Application Domain Codegen

State: **Complete**

## Contract model

- One typed Domain may contain multiple typed protobuf services.
- Each typed service declares its own stable `application.name`.
- Operation IDs and HTTP bindings remain globally unique across the manifest.
- Single-application domains retain the C8.5 generated API for zero-drift compatibility.

## Multi-application generation

For a domain with multiple applications, Yunka generates collision-free symbols per application:

- distinct Application Port interfaces derived from `application.name`;
- application-prefixed Operation constants and service-local Permission/Resolver accessors;
- `Register<Application>` RPC and REST functions and distinct server/handler types;
- a domain-level generated policy file exposing canonical `Permissions()` and `Resolver()` that aggregate every application deterministically.

No reflection or runtime registry is introduced. REST and gRPC continue to share C8.5 `OperationRuntime`.

## Verification

C8.6 requires generator unit coverage plus a real protoc-generated two-service/one-domain fixture that compiles both Application Ports, both REST/RPC adapters, and the aggregate policy runtime. Standard Yunka verify and determinism gates remain mandatory.
