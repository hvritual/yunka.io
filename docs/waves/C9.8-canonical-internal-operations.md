## Objective

Close the real cross-Application pressure discovered after C9.7 without expanding the execution runtime unnecessarily.

C9.8 proves that a canonical business Operation is not the same thing as a transport method:

```text
Canonical Operation
    ├── optional HTTP binding
    ├── optional gRPC binding
    └── internal-only
```

An internal Operation keeps stable identity, typed request/response facts, security policy, execution policy, child-operation composition, generated Application ports/capabilities and graph evidence without becoming a fake external endpoint.

## Real business proof

The C9.8 pressure slice is:

```text
device_transfer (root)
  -> site_management child: site.validate_transfer_target
  -> business decision
  -> device_management child: device.update
```

The successful MySQL 8.4 pressure run `33176909258` proved the C9.7 runtime seam with zero framework bypass:

- one root authorization decision;
- one root ExecutionScope / local UnitOfWork;
- generated `ExecuteChildTyped` capability invocation;
- no child root authorization;
- no nested child transaction;
- permission closure enforced before mutation;
- shared transaction across both child Applications.

The later contract refactor removed the fake `ValidateTransferTarget` RPC and represented it as an application-level internal Operation while preserving its OperationPlan/Application Graph/capability identity.
