# C7.3 — Legacy Runtime Removal

## Base

`main@fc9d87019be1e77cca586ed4515456603bfbd965`

C7.3 follows the C7.2 Platform Provider / Request Scope foundation and the C7.2.3 Gateway Role vertical slice.

## Goal

Make typed composition and explicit request ownership the only supported runtime model:

```text
autoload descriptor
        ↓
modulecatalog.Catalog
        ↓
core.NewApp / kernel.New
        ↓
platform.Provider
        ↓
restricted BuildContext
        ↓
App-owned stateless service
        ↓
fresh request.Context
        ↓
requestscope.Factory
        ↓
request-owned transaction + repositories
```

No compatibility fallback, service locator, reflection container, global App, or mutable request Runtime remains.

## Removed composition surface

C7.3 deletes:

- `framework/core/module` reflection construction and Service/Repository/Infrastructure pools;
- legacy `core.Module`, `core.Service`, `core.Repository`, `BaseService`, and `BaseRepository` contracts;
- `pkg/di` runtime field injection;
- package-global App/configuration/prepare/initiator/RPC holders;
- `framework/ingress` and Gateway pooled local execution;
- `ModuleGatewayProvider`, `WorkRuntimeFactory`, `GetService`, `SetRuntime`, and `PutService` RPC compatibility;
- `request.Runtime`, `WorkRuntime`, `BaseRuntime`, transaction hooks, and Runtime field mutation;
- the legacy controller generator that emitted removed composition APIs;
- the runtime-mutating ORM compatibility adapter.

The typed module generator and one-line `autoload` descriptor registration remain supported.

## HTTP request boundary

`framework/core/request.Context` is concrete and request-owned. Every inbound HTTP request receives a new instance containing:

- the parent `context.Context`, cancellation, and deadline;
- trusted `identity.Principal`;
- transport-neutral `runtimecontext.Metadata`;
- trace ID and request logger;
- fasthttp request/response state;
- one mutable request-local store.

The object is never pooled or retained by an App-owned service. Composite requests use `CloneRequest`, which creates a distinct request/response/store object, copies only request transport data, and inherits trusted context values and cancellation.

Database transaction and repository ownership does not move into the HTTP Context. It remains exclusively in `framework/requestscope`.

## Explicit Gateway execution

Gateway middleware receives `*request.Context`. `HandleMiddleware` requires an explicitly composed `bridge.Executor`. The removed local path is:

```text
App.GetModule
  → GetService
  → SetRuntime
  → business call
  → SetRuntime(nil)
  → PutService
```

Typed gRPC registers an App-owned `GatewayBusinessService` through `rpcbridge.Static` or another explicit typed provider. RPC operation metadata is derived through `context.Context`; no module pool or Runtime factory participates in the call.

JWT and in-memory SMS adapters receive configuration/logger dependencies explicitly rather than reading package globals.

## Lifecycle

`core.App` owns only:

- typed catalog module instances;
- the composition capability factory;
- logger, event bus, route tree, and lifecycle state.

Modules start in deterministic catalog order and shut down in reverse order. Platform resources follow deterministic provider ordering. Request contexts, scopes, transactions, and repositories are never part of App shutdown enumeration.

## Permanent architecture gate

`make architecture-check` requires removed paths to stay absent and rejects production use of:

- imports of `framework/core/module`, `framework/ingress`, `pkg/di`, or the legacy ORM adapter;
- `request.Runtime`, `WorkRuntime`, `BaseRuntime`;
- `ModuleGatewayProvider`, `WorkRuntimeFactory`;
- `SetRuntime`, `GetRuntime`, `PutService`, `GetRepo`, `GetInfra`;
- `RegisterPrepare`, `RegisterInitiator`, `GetApp`, `AppRegisterRpc`;
- request-lifetime `sync.Pool` in request and Gateway execution paths.

The gate does not prohibit reflection used for ordinary data binding/serialization or pools used for unrelated stateless transport buffers.

## Rollback

Revert the single C7.3 formal commit. RPC protobuf contracts and persisted schemas are unchanged. Reverting restores the legacy compatibility runtime, so rollback is a full architecture rollback rather than a supported mixed mode.
